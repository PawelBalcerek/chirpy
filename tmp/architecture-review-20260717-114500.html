Problem

Authentication logic is directly coupled inside individual HTTP handler implementations, making authentication a shallow module that lacks locality.

Solution

Consolidate authentication into a deep middleware module that validates credentials at an early seam, injecting the verified identity directly into the request context.

Wins

  • locality: credentials verified in one place
  • interface shrinks: handlers drop auth fields
  • leverage: single middleware handles all endpoints
  • locality: error handling format is uniform
  • leverage: handler tests mock context directly

Problem

Length validation and profane word filtering are implemented directly inside the HTTP handler using an incomplete loop that leaves profanities unfiltered, creating a shallow interface with leaked invariants.

Solution

Encapsulate the text body rules inside a deep Chirp text module that parses, validates, and cleans the text on construction.

Wins

  • locality: business invariants in one place
  • locality: fixes the silent profanity bug
  • interface shrinks: handler body drops text loops
  • locality: pure unit tests for validation
  • leverage: validation shared across future handlers

Problem

Individual handlers are thin wrappers around database queries and environment variables, creating a highly scattered list of route adapters in main.

Solution

Group handlers into deep domain controllers that present a unified dependency seam to main.

Wins

  • interface shrinks: setup code in main reduces
  • leverage: shared dependencies initialized once
  • locality: route grouping mirrors domain model
  • leverage: testing controllers needs fewer mocks
